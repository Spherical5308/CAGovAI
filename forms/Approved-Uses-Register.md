# Approved Uses Register: [Tool name]

> One register per approved Tool. Staff may use the Tool for any row marked **Pre-approved** for their audience, with no Request, as long as no [Trigger](../standards/Data-and-Tier-Floor-Standard.md#2-triggers) applies. Anything else needs a Request.
>
> Categories follow SIMM 150 (General Office Productivity). The audience columns follow the State of Oregon's Copilot use matrix (107-004-200, Attachment A), cited as a reference.

> **How to complete this register**
> - **Who:** the Tool owner proposes it as part of the Request that introduces the Tool (Procedure 01, section 5). The Committee approves it.
> - Start from the defaults below. For each row and audience, choose one of the four Legend values, and tighten any that do not suit the Tool or your data. Remove rows for features the Tool does not have.
> - Adding a row or loosening a value later is a Material Change and goes back to the Committee.
> - Once approved, publish the register where staff look for AI guidance and link it from the AI Inventory (`approved_uses_register`).

## Legend
- **Pre-approved**: go ahead; you must still verify output (SAM 4986.12).
- **Pre-approved, documented review**: go ahead; a second qualified person reviews and the review is noted with the final product.
- **Request**: submit a Request first.
- **Not permitted**: do not use the Tool for this.

## Always needs a Request, whatever the row says
- Any Confidential/Sensitive, Personal or Federally restricted data not listed above as approved for this Tool.
- Any decision about a specific person.
- Any Autonomy Level A2 or A3.
- Anything about employees' performance, discipline or monitoring.

## Disclosure reminder
If GenAI created or substantially altered content that goes to the public, label it and give a way to reach a person (GC 11549.66). Light editing or proofreading of human-written work does not need a label.
